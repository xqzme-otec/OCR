# Постобработка OCR паспорта РФ: отчёт

## Прогноз для test

**Примем 1178 из 2000 документов (58.9%). Из них с ошибкой ожидаем около 11 (95% интервал 6–16).**

Оценка сделана по кросс-валидации (5 фолдов) на train по исходной разметке. При том же пороге принято 1772 из 3000 (59.1%), из них 15 с ошибкой (0.85%, 95% интервал 0.47–1.39%). С учётом другой доли источников в test (mobile_v2 22% против 10%) и ошибок по источникам на train (web 0.9%, mobile 0.5%, mobile_v2 1.9%) получается 11.3 ошибки.

12 из 15 ошибок на train — опечатки разметки, которые во входных данных не видны (см. ниже). Реальных ошибок системы 3 из 1772. Поэтому меньше ~0.7% ошибок среди принятых на этих данных получить нельзя.

## Что сделано

Конвейер `postprocess.py`: значения полей → жёсткие правила → модель уверенности → порог.

**1. Сбор значений из нескольких источников** (`pp/resolve.py`)
- **MRZ** (`pp/mrz.py`): серия и номер, даты рождения и выдачи, код подразделения, пол. У каждого блока своя контрольная цифра. Строка 2 разбирается с обоих концов, поэтому вставка или пропуск символа портит только композитную контрольную цифру. Век в датах однозначен: паспорт с 14 лет, новые паспорта с 1997 года.
- **Даты, номер, код.** Если визуальная зона совпала с MRZ или MRZ прошла контрольную цифру, на train это **100%** верных значений (≈2700 на поле). Если значение есть только в визуальной зоне, верных 95%.
- **ФИО.** Таблица транслитерации МВД (Й→Q, Ч→3, Ш→4, Я→8…) выведена и проверена по разметке. Ожидаемая строка 1 MRZ строится из визуальной зоны и выравнивается с прочитанной целиком, поэтому типичный сбой MRZ `<`→`K` не сдвигает поля. Буква, которая есть в MRZ на краю поля, но потеряна в визуальной зоне (`FUDOROVI3` при `УДОРОВИЧ`), считается расхождением. Если источники расходятся в одном символе, выбираем тот, у которого выше уверенность в этом месте (96% верных при разнице ≥ 0.05).
- **Пол:** голосование визуальной зоны, MRZ и окончания отчества (-ВИЧ/-ВНА/ОГЛЫ/КЫЗЫ). На train 3000 из 3000.
- **Место рождения и «кем выдан»:** исправление слов по словарю (справочник + разметка train, поиск SymSpell, расстояние Дамерау-Левенштейна). Исправляем только слова с уверенностью OCR < 0.95, длиной ≥ 4, с однозначным кандидатом и не «потерянную пунктуацию» (`ГМОСКВЕ`→`МОСКВЕ`, на деле `Г.МОСКВЕ`). Иначе редкие сёла «исправляются» в частые слова: без порога по уверенности правильных мест рождения становится не больше, а меньше (1906 вместо 2481).

**2. Жёсткие правила** (`pp/model.py: gate`): отклоняем, если
- паспорт недействителен на 01.10.2026 (`pp/validity.py`): выдан до 14 лет или в будущем; держателю исполнилось 20/45 после выдачи. **90 дней после 20/45 лет** паспорт формально ещё действует, но только пока не получен новый. Из данных это не узнать, поэтому такие документы тоже отклоняем (на train их 15);
- пустое поле, или поле, продублированное в MRZ, не подтверждено ей;
- **потеряна строка**: высота рамки поля больше, чем у прочитанных строк. На train 72 из 72 таких полей ошибочны.

**3. Модель уверенности.** На каждое поле `HistGradientBoostingClassifier` предсказывает P(поле верно). Признаки: уверенность по символам (мин., среднее, число низких), источник значения и согласие с MRZ, статистика словарных исправлений (сколько слов вне словаря, уверенность в неисправленной части, частота первого и последнего слова для поиска обрезанного текста), качество снимка, источник. P(документ) — произведение по полям. Модель учится только на документах, прошедших правила. Признаки train считаются со словарём **без разметки своего фолда**, как будет на test.

Гиперпараметры подобраны случайным поиском по 60 конфигурациям на двух разбиениях на фолды (`tune.py`). Разница между лучшими конфигурациями в пределах шума (±1 ошибка), поэтому оставлены умеренные: 300 деревьев, lr 0.05, 15 листьев, ≥ 20 примеров в листе. Сравнение на тех же признаках (`compare_models.py`), ошибок среди 1800 самых уверенных документов: бустинг 16, логистическая регрессия 27, нейросеть (MLP) 29 (лучшая из четырёх настроек). Данных мало (~2300 документов, ошибочных полей десятки), признаки табличные с порогами, и деревья здесь сильнее.

**4. Порог 0.995.** Доля ошибок в OOF по интервалам P:

| P(документ) | ≥0.9995 | 0.999–0.9995 | 0.998–0.999 | 0.995–0.998 | 0.99–0.995 | 0.98–0.99 | 0.95–0.98 |
|---|---|---|---|---|---|---|---|
| документов | 1223 | 270 | 160 | 119 | 47 | 33 | 53 |
| ошибок | 0.8% | 0.7% | 1.2% | 0.8% | 8.5% | 6.1% | 11.3% |

Выше 0.995 доля ошибок ровная, это уровень шума разметки, и строже порог её не снижает. Ниже она скачком растёт до ~9%.

## Как растёт качество (train, OOF)

| Вариант | Принято | С ошибкой |
|---|---|---|
| Склеить строки OCR и принять всё | 3000 | 1385 (46%) |
| Только жёсткие правила | 2284 | 339 (15%) |
| Правила + модель, порог 0.995 | 1697 | 18 (1.06%) |
| + исправлены 2 бага сверки ФИО с MRZ | 1717 | 14 (0.82%) |
| **+ модель обучена на разметке без опечаток ФИО** | **1772** | **15 (0.85%)** |

После всех исправлений верны и действительны 2156 документов (72%), без исправлений 1615. Модель отбирает из них 1757.

## Что выяснилось о данных

- **Шум в разметке.** В 11 документах train визуальная зона и MRZ согласованно и уверенно (≥ 0.99) показывают `ЕВГЕНИЙ`, `БАЛТРУШЕЕВИЧ`, `ФАРИДА`, а в разметке `ЕВТЕНИЙ`, `ЬАЛТРУШЕЕВИЧ`, `ФАРИЛА`. MRZ генерируется из истинного значения (см. следующий пункт), так что это опечатки разметки, похожие на ошибки OCR. Ещё одна такая опечатка в месте рождения (`ДЖАМБИУИ` вместо аула Джамбичи). Опечатки ФИО `train.py` находит сам (viz = MRZ, уверенность всех букв ≥ 0.99, разметка отличается на один символ) и исправляет **только для обучения**: модель перестаёт «бояться» идеально выглядящих ФИО (+55 принятых при том же числе ошибок). Качество и прогноз считаются по исходной разметке, потому что в test, скорее всего, такой же шум. Это основная часть ошибок среди принятых.
- **Опечатки, которые есть в самом документе.** `ММИХАЙЛОВИЧ`, `ВЛАДИСЛАОВНА` есть и в разметке, и в MRZ. Значит, ФИО нельзя «исправлять» по словарю имён, только по MRZ.
- **Справочник подразделений не совпадает с разметкой дословно** (`ОБЛ.`↔`ОБЛАСТИ`, `РАЙОНЕ`↔`Р-НЕ`, добавлено «ОТДЕЛ ПО ВОПРОСАМ МИГРАЦИИ»). Брать название из справочника по коду нельзя, его можно использовать только как словарь слов.
- **`mobile_v2`: уверенность бесполезна.** У 91% полей `conf = 1.0`, в том числе у ошибочных. Отсюда меньше принятых (51%) и больше ошибок (2.1%). В test этого источника вдвое больше.
- **Контрольная цифра MRZ не видит замену цифры на букву** со значением +10 (`6`↔`G`, `0`↔`A`, `8`↔`I`, `<`↔`K`). Перед проверкой буквы в числовых позициях приводятся к цифрам.
- **Пробел после точки** (`С.ГУЖОВО` / `С. ГУЖОВО`) встречается в разметке в обоих вариантах. OCR теряет его примерно в 4% случаев, и восстановить его нельзя. Это остаётся признаком риска для модели.
- **3% паспортов train просрочены** (держателю исполнилось 20 или 45 лет).

## Что не сделано и что можно улучшить

- Документы без MRZ (≈6%) отклоняются целиком: даты и номер без MRZ верны лишь на 95%.
- ФИО, которые детектор визуальной зоны не нашёл, можно брать из MRZ (≈1.5% документов). У строки 1 нет контрольной цифры, нужна отдельная проверка точности.
- Для места рождения нет внешнего источника. Справочник населённых пунктов (ФИАС/ОКТМО) заметно поднял бы долю принятых.
- Порог выбран без явной стоимости ошибки. Если известно соотношение «цена ошибки / цена отказа», порог можно вычислить по таблице выше.

## Запуск

```
pip install -r requirements.txt
python postprocess.py data/test_predictions.jsonl answers.jsonl   # ~3 с, CPU, без интернета
python train.py --oof-answers oof.jsonl                           # переобучение + отчёт OOF (~20 с)
python evaluate.py oof.jsonl data/train_labels.jsonl
```
